## 关键决策

- 将项目定义为“多模型 agent 编排配置模板”，不描述为可直接运行的应用或框架。
- 使用一份角色表和一条典型流程同时解释 Claude Code 与 Codex，平台差异只在配置章节呈现。
- 快速配置采用复制 agent 文件、合并指令文件的方式；目标位置已有 `CLAUDE.md` 或 `AGENTS.md` 时，明确禁止直接覆盖。
- README 只概述规则并链接到真实文件，不重复粘贴完整 agent 定义或工程规范。
- 不保留仓库无法证明的固定价格、偶然 token 数据、重启要求、内置 Explore 模型归因或 MIT 声明。

## 风险

- 用户直接复制指令文件可能覆盖项目已有规则；通过醒目提示和合并命令规避。
- 模型名称与工具版本可能变化；README 仅记录当前模板映射，并提示按本地可用模型调整。
- 仓库没有自动化测试；验证以文件、链接、命令和内容一致性检查为主。

## 验证标准

- README 明确覆盖项目定位、角色分工、典型流程、两平台快速配置、验证方法、仓库结构和必要注意事项。
- 所有相对链接均指向仓库中存在的文件。
- 复制命令的源路径与仓库结构一致，且不会指导用户覆盖已有项目规则。
- 不含过时重启说明、Explore 固定模型判断、偶然 token/价格数字或无依据的 License 声明。
- 除本计划文档与 `README.md` 外无文件变更。

## Review Notes

### 发现的问题

- 用户级 agent 安装命令使用普通 `cp` 向已有目录批量复制；遇到同名文件时会静默覆盖用户现有的 Claude Code 或 Codex agent 定义。
- 验证章节未限定 `/agent` 的适用界面，可能让读者误以为所有 Codex 客户端都提供该命令。

### 根因

- 初版只处理了 `CLAUDE.md` 与 `AGENTS.md` 的覆盖风险，遗漏了 agent 定义同样属于用户配置。
- 将 Codex CLI 的验证方式简称为“Codex”，界面范围表述不够精确。

### 修复

- 将两组 agent 安装命令改为逐文件 `cp -i`，并明确要求同名文件存在时拒绝覆盖、比较后手动合并。
- 将 `/agent` 明确限定为 Codex CLI；其他客户端只建议使用其提供的 agent 状态或日志，不承诺具体界面能力。
